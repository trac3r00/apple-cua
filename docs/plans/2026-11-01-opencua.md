# OpenCUA plan (2026-11-01)

Coordinator: the main OmO session. Workers are delegated tracks with disjoint write scopes.
Shared files reserved to the coordinator: `packages/core/src/index.ts`, `packages/mcp/src/server.ts`,
`packages/mcp/src/tool-names.ts`, root `package.json`, `pnpm-lock.yaml`.

## Final users

1. An AI agent (Claude Code, Codex, OmO, Cursor) that calls OpenCUA through MCP or the CLI. It needs a short,
   unambiguous skill, stable tool names, fast responses, explicit error codes with retry guidance, and the same
   observe -> act -> verify loop on every OS.
2. The person who installs it. They need one install command per OS, a working upgrade from apple-cua
   (permissions, MCP registrations, history data and settings preserved), and an agent that never takes their
   mouse, keyboard focus or screen.

## Gaps (current -> ideal)

- G1: Everything is named apple-cua. Rename done mechanically on 2026-11-01. Compatibility shims and migration are pending.
- G2: setup.sh is macOS-only. There is no Windows installer and no Linux path.
- G3: `QemuComputer`/`CloudComputer` are stubs, and there is no Linux or Windows host backend.
- G4: There are no snapshot-scoped refs, error dispositions, skills-from-binary, clipboard or notification tools (audit pending).
- G6: The skill is 444 lines, and the agent has to read all of it.
- G8: Skills from history require a localhost UI and a separate OmO model call. There is no repeat detection.
