## User and ideal result

The user is an agent operator completing browser and macOS tasks from OpenClaw,
Hermes, Doldori (clarified from Dori), Omocat, OmO, Claude Code, or Codex. They need the same observable MCP
contract regardless of client: discover tools, observe an approved app, act on the
observed target once, verify the effect, and recover without replaying input.

The ideal result has:

- Scoped targets and single-use observation tokens, preventing stale input.
- Structured results and JSON text fallback, usable without client elicitation.
- Multi-step workflows with explicit failure boundaries and verified readback.
- Correct stdio framing and request correlation under concurrent calls.
- Honest disconnect reporting without automatic mutation replay.
- Measured browser and desktop outcomes, not superiority inferred from feature lists.

QA scenarios:

1. Observe, change a field, continue using the returned token, verify the value,
   and reject replay of the original token without extra input.
2. Run a failing batch, inspect the failure boundary, observe again, and complete
   a subsequent operation without duplicate mutation.
3. Exercise clients with and without elicitation; missing elicitation must return
   a structured human handoff rather than assume consent.
4. Send concurrent stdio requests and return answers out of order; each caller
   must receive its own result.
5. Split JSON across stream writes; complete newline-delimited messages must
   decode exactly once.
6. Exit with multiple requests pending; all must reject and pending state must
   clear. Later calls must report server death, never replay input.
7. Drive local browser forms and a multi-window or cross-app desktop task; verify
   through an independent oracle and restore scratch state.

## Comparison rules

Compare identical fixtures and outcomes on the same machine. Record success,
false completion, call count, payload bytes, latency, focus disturbance, and
recovery behavior. Keep scripted driver comparisons separate from model-driven
agent comparisons. Cua Driver is not automatically a substitute for Codex's native
plugin, and attached-browser readiness is not an OmO benchmark result.

Client configuration support, protocol conformance, live MCP connectivity, and
end-to-end agent task completion are separate evidence levels. Do not label a
client certified from an in-memory SDK test or claim universal superiority from
unmatched runs.

### Matched task and production regression fix

With the user keeping the task-only window open, apple-cua resolved Code, wrote
the value, read it back, and passed a separate `verify_state`. The independent
page report agreed. The same semantic field task passed through both native
computer AX and the attached DOM browser.

One run per route, excluding fixture setup:

| Route | Calls | Elapsed |
| --- | --- | --- |
| apple-cua `run_script` | One MCP call, three guarded actions | 574.66 ms |
| OmO native computer AX | Three facade calls | 1,464.72 ms |
| OmO attached DOM browser | Snapshot, fill, evaluate | 63.49 ms |

The guarded bundle was about 2.55 times faster than three native computer calls
in this sample, but the DOM browser was about nine times faster than the guarded
bundle. Different transports and checks matter; n=1 is not a throughput,
reliability, or universal superiority claim. Native background keystrokes also
refused ambiguous multi-window delivery, while apple-cua used an explicit window
binding. Both are useful safety contracts.

Chromium's [accessibility documentation](https://www.chromium.org/developers/design-documents/accessibility/)
explains lazy AX activation through `AXEnhancedUserInterface`. apple-cua has no
explicit activation in the inspected path; native full-tree reads and foreground
setup preceded page controls appearing. The precise causal mechanism is still
unconfirmed, so no speculative change was made to the pre-existing core edits.
Background omnibox navigation was not reliable in these runs; foreground Return
was required for fixture setup.

The reproduced reporting defect was independent: File/New Window returned a
real `windowEvents` entry while the old window's AX tree remained unchanged.
`tool-result.ts` now reports `observed_change` with only `window_change` evidence,
not `suspected_noop` or fabricated AX evidence. It preserves refusal, partial,
verified-result, and token precedence. Three new regressions failed before the
fix and passed afterward. A fresh built stdio server reproduced the corrected
live result without a false no-op escalation.

The two task windows were closed, attached sessions stopped, oracle servers
closed, and the fresh MCP test process exited with code 143 after SIGTERM.
Evidence: `.omo/evidence/chrome-matched-scenario-20261009.json`.

The final framing regression accumulates arbitrary stream chunks before
acknowledging the first seven-byte prefix; it does not assume one event equals
one write. The review finding was corrected and the full checks passed again.
Inspected benchmark scratch files and `/tmp/cua-bench` were removed afterward.

No repository commits or client registrations were made. The four pre-existing
CLI/core file changes and the pre-existing harness documentation changes were
preserved. The discarded fixture attempt leaves no diff in `attempt.mjs` or
`oracle-server.test.mjs`. Final `git diff --check` passed; no task-created gstack
